## 循环目标

**本循环专注打磨「强化学习」板块**(限「🕹️ 强化学习」域下的教程),把它建成全站最完整、最权威的一块。

**每轮都要把下面 1 → 2 → 3 → 4 → 5 → 6 六个步骤依次各处理一遍**(不是选择性挑一个单点):先做关键词侦察、再审阅与调整 RL 教程大纲档,然后按内容(含参考资料)→ 正确性 → UI/视觉 → 代码/工程的顺序落改进,六步做完再收尾小结。

> **每轮都要「贪多」——改动量要肉眼可见地大,别小打小闹。** 六步里:
> - **步骤 3「内容」是绝对重头戏,每轮至少落 2 处「大块」改动**(如「新增一个完整小节 + 一个新交互 viz」「一篇深化重写 + 配套可运行示例」「一次章节重组 + 一段冗余合并」),而不是只补一处、更不是只加一句话或一个 FAQ 条目。**「大块」既指扩充(把板块变厚),也指结构重组与内容重构(把骨架/表达变优)——两者同等分量。** 宁可这一步多花时间,也要让板块每轮都明显变强。
> - **步骤 4/5/6 每步至少落 2-3 处改进**(不再是「单点」):步骤 4 巡检并修多处正确性/一致性问题、步骤 5 走查并优化多处 UI/视觉/动画、步骤 6 清理多处工程债。只有当某步确实扫不出第 2 处有价值的改动时,才降到 1 处并写明原因。
> - 总原则:**每轮的 diff 应当是「一大块内容 + 若干实打实的改进」的组合拳,而不是「一处大块 + 三处一句话」。** 觉得改得太少,就是没做够——回到步骤 3 再加一块,或在 4/5/6 多扫几处。

> **两个例外**:
> - **新建教程占满一轮**:当本轮步骤 3 决定新建一篇教程(如 DQN、REINFORCE),新建 + 注册 + 更新大纲档 + build 本身就是一整轮工作量;该轮只做「步骤 1 侦察 + 步骤 2 审阅大纲档 + 步骤 3 建教程 + build」,步骤 4/5/6 顺延到下一轮。**连续两轮新建后,第三轮应优先补做积压的正确性/UI/工程改进**,避免 4/5/6 长期欠债。
> - **某步扫不出足量高价值改动**:不为凑数硬堆无意义 diff。**步骤 4/5/6 的目标是每步 2-3 处改进;若某步认真巡检后确实只找到 1 处、甚至 0 处有价值的改动,可降级并写明「本步只落 N 处 / 无改动,原因:…」。** 但降级是例外而非常态——多数轮次这三步都应能扫出 2-3 处,写「无改动」前先问自己是否真的巡检到位。**此例外完全不适用于步骤 3「内容」**——步骤 3 是每轮重头戏,必须有至少 2 处实质的「大块」改动(扩充或重构均可);若真找不到点子,应主动侦察新主题/新教程、或挑一篇结构最乱的做重组,而不是缩水。

> **处理顺序与优先级**:
> - 每轮固定按 1 → 2 → 3 → 4 → 5 → 6 依次全部走一遍,无需询问。
> - 本循环范围限定在**强化学习板块**;其它领域仅在顺手发现明显 bug/悬空引用时才捎带修。

- **`arxiv-search`**:按关键词检索 arxiv 上的经典/前沿 RL 论文,发现该主题的奠基作与最新进展(如 DQN、PPO、SAC、GAE、DPO、GRPO 等原文)。用它定位「该引哪篇」。
- **`read-arxiv-paper`**:拿到具体的 arxiv URL 后,用它精读该论文,提取权威定义、核心公式、原始图示、作者原话与实验结论,作为步骤 3 正文论断与参考资料的一手依据。用它搞清「这篇到底讲了什么」。
- **联动约定**:`arxiv-search` 发现线索 →`read-arxiv-paper` 深读原文 → 步骤 3 落成正文引用与「参考资料」条目(优先 arXiv `abs` 稳定地址)。**每轮至少用一次这两个 skill 中的一个**,让内容「有原始论文可查」。
- **`deep-research`(可选,重型侦察)**:若本轮要为某主题做成体系的大块扩充或新建教程,可直接动用 `deep-research` 做一次多源扇出 + 对抗式核验的综述侦察,一步到位摸清该主题全貌与权威出处;它比单点搜索更全,产出可直接喂给步骤 3(详见步骤 3 说明)。

- **策略与深度 RL**:policy gradient、REINFORCE、actor-critic、A2C/A3C、advantage function、GAE、PPO、TRPO、DDPG、SAC、TD3、DQN、experience replay、target network

- **概念/教学**:credit assignment、discount factor、reward shaping、gridworld、multi-armed bandit、model-based RL、offline RL

### 步骤 3:教程内容专项(每轮重头戏,要「大块」改动)
强化学习教程的深度、广度与组织。**「大块」不只是「往里加东西」,还包括大刀阔斧的结构重组与内容重构**——把一篇里散落的知识点重新编排成有递进的章节、把讲重了的内容合并去冗、把一节拆成逻辑更清晰的多节、把顺序错乱的推导理顺,都是同等分量的「大块」产出。加法(扩充)与重构(不加甚至减字数却让结构/表达明显更优)一视同仁,不要因为「重构不涨行数」就觉得分量不够。

> **「大块」改动可先用 `deep-research` skill 打底(推荐)**:当本轮要新建一篇教程或对某主题做成体系的深化/重构时,`deep-research` 能一次性把该主题**扇出多源搜索 → 抓取权威来源 → 对抗式核验论断 → 产出带引用的综述**,正好为「有推导、有对比、有据可查」的大块内容与末尾「参考资料」小节打底,也能帮你判断某篇现有结构该如何重组。它与步骤 1 的 `arxiv-search`/`read-arxiv-paper` 互补:后者精准定位与精读单篇原始论文,`deep-research` 覆盖面更广、自带交叉核验,适合摸清一个主题的全貌。产出仍要由你消化后用中文改写进正文(不可直接粘贴),引用落成稳定 arXiv/DOI 地址。

- **本步目标:每轮至少落 2 处「大块」改动**,让板块肉眼可见地变强(更厚、或结构更清晰、或表达更精准)。合格的单处产出应达到下面**任一项**的量级,而单轮应凑够**至少两项**(可同类两项、也可跨类组合,如「一个完整小节 + 一次章节重组」「一个新交互 viz + 一段冗余合并」):
  - **扩充**:给某篇教程**新增一个完整小节**(概念讲解 + 至少一个可运行 Python 示例/交互 viz + 典型案例或易错点),而非只加一段话或一个 FAQ 条目;
  - **新建一篇教程**(走「新建教程占满一轮」的例外流程,此时该轮 Step 3 只此一项即够);
  - **新建一个交互 viz** 并配套讲解文字嵌入正文;
  - **重写/深化**:对某篇做成体系的重写(如把浅尝辄止的一节扩成含推导、图示、代码、对比表的完整章节);
  - **结构重组**:对一篇(或跨篇)做**章节级的重新编排**——调整小节顺序理顺递进、拆分臃肿章节、合并重复内容、抽出共性小节、重排 prev/next 学习路径,使整体骨架明显更优(即便净字数持平或减少);
  - **内容重构**:对现有内容做**成段的重述/订正**——统一术语与符号、改写晦涩推导、替换失准表述、把零散论断整理成对比表或分点,使可读性与准确性明显提升。
  - **量级底线**:以「扩充/新建」为主的产出,单轮净新增正文应达到**约 150 行以上**(viz 组件代码另计);以「结构重组/内容重构」为主的产出可不涨行数,但改动应覆盖**至少一个完整章节或跨多个小节**、且能一句话说清「重构前 → 重构后」结构或表达如何变优。无论哪类,若感觉分量单薄,回头再加一块。
- **调整**:修正过时/不准的表述,对齐步骤 1 搜到的权威讲法,理顺学习路径(期望主线见 `.claude/local/memory/rl-tutorial-structure.md` 的「学习路径递进核对」小节,需调整时改那里而非本文件)。
- **优化**:补交互式 viz(gridworld、Q 表演化、bandit、PPO 裁剪目标曲线)、可运行 Python 示例、典型案例、面试 FAQ、动手作业。
- **补充**:填补明显缺口(如 DQN、policy gradient/REINFORCE、actor-critic、多臂老虎机、Bellman 方程等尚无独立教程的核心主题)。
- **参考资料与权威链接(必带)**:正文每一处论断、公式、图示凡引用步骤 1 侦察到的权威讲法,都要补**可点击的正式出处**,让内容「有据可查」。
  - **优先权威来源**(按可信度排序):原始论文(arXiv / 出版社 DOI / NeurIPS·ICML·ICLR·AAAI 官方页面)、经典教材(Sutton & Barto《Reinforcement Learning: An Introduction》、Silver 经典 RL 课、Levine CS285、Berkeley/Stanford 公开课)、权威综述(Schulman GAE、Haarnoja SAC、Schulman PPO 等)、知名高质量博客(Lilian Weng、Spinning Up、HuggingFace Deep-RL Course)。**原始论文类来源优先用步骤 1 的 `arxiv-search` / `read-arxiv-paper` skill 亲自查到与精读过的 arXiv 论文**,而非二手转述。
  - **链接规范**:用 Markdown 标准链接 `[文本](URL)`,URL 用**稳定地址**(优先 arXiv `abs` 页、DOI、官方课程页,避免易失效的临时页面);中文译名后括注英文原名与年份,如「近端策略优化(PPO,Schulman et al., 2017)」。
  - **每篇教程末尾设「参考资料」小节**:汇总该篇引用的论文/教材/讲义/博客,统一编号;正文出现处用 `<Cite n={N} />` 角标(多条用 `<Cite n={[1,4]} />`,组件已全局注册)或在行内括注链接。**新教程必带,老教程逐轮补齐**;新建/重写一篇时,参考资料与正文同步落地,杜绝「内容写好了却没出处」的悬空论断。
  - **与步骤 1 联动**:步骤 1 搜到的权威讲法在本轮若被写进正文,出处必须在本步落成正式引用。
- **反面清单(不要这样做)**:只补一个 FAQ 条目、只改几句措辞——这些太单薄,不算合格的产出;堆砌一堆没在正文用到的「扩展阅读」链接充数、引用个人技术掘金/知乎二转文而非原始来源、用不稳定的短链/网盘链接、只给裸 URL 不给标题与作者。宁可少走一步流程,也要让内容有分量。

### 步骤 4:正确性(本轮至少落 2-3 处)
网站能用、内容不误人。**主动巡检,别只盯着本轮 Step 3 新增的部分——把整个 RL 板块扫一遍,列出发现的问题再逐一修。**
- 功能 bug:渲染错误、交互异常、SSR/水合不一致、边界条件崩溃
- 数值/知识正确性:viz 数学公式、Python 示例、图表数值(用 `python3`/`node` 独立复算)、教程表述无硬伤
- 悬空引用:被正文引用却无页面/无锚点的概念
- **注册表 / 文件系统一致性**:核对 `src/lib/tutorials.ts` 中 `category === "强化学习"` 的条目与 `src/app/tutorials/<slug>/page.mdx` 一一对应——无孤儿(注册表有但磁盘缺)、无幽灵(磁盘有但注册表未注册);slug / title / topic / icon / prev-next 顺序与磁盘实际一致。发现偏差立即修(补建缺失 `page.mdx`、补注册条目或删孤儿),修后同步 `.claude/local/memory/rl-tutorial-structure.md`

### 步骤 5:UI / 视觉(本轮至少落 2-3 处)
看得舒服、各终端各主题都正常。**逐轮轮换走查不同教程页与 viz,别每轮只碰本轮新建的那个组件——挑 2-3 处最值得优化的落改。**
- 布局排版:三栏 layout、间距留白、字号层级、正文可读性、代码块与表格样式
- 图表视觉:SVG 配色、坐标轴/图例清晰度、响应式(`viewBox` + `max-w-full`)、窄屏不溢出
- 暗色模式:逐组件走查明暗两套,用 `--chart-*` 等主题变量而非硬编码 hex
- 响应式:移动(抽屉导航)/ 平板 / 桌面三档断点的布局与可点击区域
- 交互反馈与一致性:hover/active/focus/loading/禁用态反馈;viz、Slider、按钮的颜色/圆角/阴影统一
- **动画与过渡**:状态切换、数据更新加平滑过渡(CSS `transition`/`@keyframes` 或轻量动画),让 viz「活」起来——gridworld 智能体逐步移动、Q 表热力图随训练演化、bandit 拉杆反馈、PPO 裁剪曲线随参数滑动、滑块拖动时几何平滑过渡。优先 CSS/transitions,避免引入重动画库;时长 150-400ms,缓动用 `ease-out`/`cubic-bezier`,勿线性生硬
- 可访问性:SVG `role`/`aria`、键盘可达性、颜色对比度;**动画必须尊重 `prefers-reduced-motion`**(给晕动症用户降级为即时切换或关闭)

### 步骤 6:代码 / 工程(本轮至少落 2 处)
长期可维护(锦上添花)。**扫一遍 RL 相关组件与工具函数,挑 2 处以上工程债清理。**
- 重构:去重、抽取共用逻辑与组件、收敛类型定义、消除 `any`
- 性能:不必要的重渲染、过大依赖、可延迟加载的模块
- 健壮性:错误边界、加载失败兜底、类型安全、清理构建告警

## 关键技术约束(踩过的坑)

- **matplotlib 图表**:CodeRunner 现已支持内联渲染 PNG(见 `.claude/local/memory/coderunner-matplotlib-support.md`)。**图表标签必须用英文** —— Pyodide 只带 DejaVu 字体,中文会渲染成方框(□□□)。正文散文保持中文。
- **编辑 `public/pyodide-worker.js` 需硬刷新 / 重启 dev server** —— 它是经典 Web Worker,不在模块图里,HMR 不生效。改 `next.config.ts` 同理需重启。
- **Turbopack 要求可序列化的 MDX 插件配置**:remark/rehype 插件用字符串名 `[["remark-gfm"]]`,不能 import 函数。
- **表格靠 `remark-gfm`**:Markdown 表格是 GFM 扩展,已在 `next.config.ts` 启用 `remark-gfm`(否则表格渲染成裸文本)。
- **客户端组件随路由更新**:App Router 软导航切教程时 layout 不重挂。依赖 DOM 的客户端组件(如 `TableOfContents`)effect 要依赖 `usePathname()`,否则内容停留在上一篇。
- **viz 渲染期禁用随机**:交互组件不要在渲染路径调用 `Math.random()`/`new Date()`(SSR/水合不一致)。随机只在用户交互回调里触发,或用确定性伪随机(按索引 seed)。
- **响应式 SVG**:所有 viz 的 `<svg>` 用 `viewBox` + `max-w-full h-auto`,否则窄屏溢出。带点击坐标映射的组件(如 ScatterClassifier)要按 `rect.width/height` 把点击换算回 viewBox 坐标系。
- **侧栏滚动**:三栏 layout 的 sticky 侧栏用 `max-h-[calc(100vh-6rem)] overflow-y-auto`,内容超高时才能独立滚动。
- **动画与水合**:动画只挂在客户端,且**不要在首次渲染就跑依赖随机/时间的动画**(SSR HTML 与客户端首帧不一致会触发水合警告)。用 `useEffect` 里置 `mounted=true` 再启动动画,或用 `requestAnimationFrame` 在挂载后驱动。`@media (prefers-reduced-motion: reduce)` 下降级为瞬时切换。SVG 属性动画(SMIL `<animate>`)在部分浏览器不稳,优先 CSS animation 或 JS 驱动。
