# 🔁 交叉验证

[模型评估](/tutorials/model-evaluation)那篇里,我们把数据切成训练集和测试集。但只切**一次**靠谱吗?万一这一刀切得「运气好/运气差」,评估结果就会有偏差。**交叉验证(Cross-Validation)** 用一个聪明的办法解决它,也是[选超参数](/tutorials/overfitting-regularization)(K、深度、正则强度 λ)最可靠的工具。

> 一次考试发挥失常不能说明真实水平。考很多次取平均,才公平。交叉验证就是让模型「多考几次」。

## 单次划分的问题

把数据一次性切成 80% 训练 + 20% 测试,有两个隐患:

1. **结果看运气**:恰好把「难样本」都分到测试集,分数就偏低;反之偏高
2. **数据浪费**:那 20% 从不参与训练,小数据集尤其可惜

## K 折交叉验证:让每个样本都当一次「考官」

**K 折交叉验证**把数据均分成 K 份(「折」),然后:

1. 轮流拿其中 **1 折当验证集**,其余 **K−1 折当训练集**
2. 训练 + 评估,记下这一轮的分数
3. 重复 K 轮,直到**每一折都当过一次验证集**
4. 最终成绩 = K 轮分数的**平均**(还能看标准差,判断稳定性)

下面**拖动折数 K**,看橙色验证集如何沿对角线移动 —— 每个样本恰好被验证一次,数据被充分利用:

<KFoldExplorer />

- **K 越大**:每轮训练数据越多(偏差小),但要训练 K 次(更慢);极端是 K=N 的「留一法(LOO)」
- **K 越小**:快,但每轮训练数据少、评估方差大
- 实践中 **K=5 或 K=10** 是最常用的折中

## 用 scikit-learn 实现

`cross_val_score` 一行完成 K 折评估,返回每一折的分数:

<CodeRunner
  packages={["scikit-learn"]}
  defaultCode={`
import numpy as np
from sklearn.datasets import load_iris
from sklearn.neighbors import KNeighborsClassifier
from sklearn.model_selection import cross_val_score

X, y = load_iris(return_X_y=True)
model = KNeighborsClassifier(n_neighbors=5)

# 5 折交叉验证
scores = cross_val_score(model, X, y, cv=5)
print("每折准确率:", scores.round(3))
print(f"平均: {scores.mean():.3f}  (± {scores.std():.3f})")
print("\\n比起单次划分,这个平均值更能代表真实泛化能力。")
`} />

## 经典用途:用交叉验证选超参数

交叉验证最重要的应用是**公平地挑超参数**。下面用它给 KNN 选最佳的 K —— 每个候选 K 都做一次交叉验证,选平均分最高的:

<CodeRunner
  packages={["scikit-learn"]}
  defaultCode={`
import numpy as np
from sklearn.datasets import load_iris
from sklearn.neighbors import KNeighborsClassifier
from sklearn.model_selection import cross_val_score

X, y = load_iris(return_X_y=True)

print(" K | 交叉验证平均准确率")
print("---|------------------")
best_k, best_score = 0, 0
for k in [1, 3, 5, 7, 9, 15, 25]:
    s = cross_val_score(KNeighborsClassifier(n_neighbors=k), X, y, cv=5).mean()
    bar = "█" * int(s * 30)
    print(f"{k:2d} | {s:.3f} {bar}")
    if s > best_score:
        best_k, best_score = k, s
print(f"\\n最佳 K = {best_k}(平均准确率 {best_score:.3f})")
`} />

> 💡 这正是 `GridSearchCV` 的核心思想:对一组超参数组合,逐个做交叉验证,自动选出最优。

## 典型应用场景

- **超参数调优**:配合 `GridSearchCV` / `RandomizedSearchCV` 网格搜索最佳参数
- **模型选型**:在同一份数据上公平比较多个模型(KNN vs 逻辑回归 vs 树)
- **小数据集**:数据少时单次划分太浪费,交叉验证让每个样本都参与训练
- **评估稳定性**:K 折分数的标准差能反映模型对数据划分的敏感程度

## 常见问题 FAQ

**Q:K 取多少合适?**
最常用 **5 或 10**。K 太小评估方差大,K 太大计算慢且每折训练集高度重叠(收益递减)。数据极少时可用留一法(K=N)。

**Q:类别不平衡时要注意什么?**
用**分层 K 折(StratifiedKFold)**,保证每一折里各类别比例与整体一致 —— `sklearn` 对分类任务默认就用它。

**Q:交叉验证能完全替代独立测试集吗?**
不能。调参时如果反复用同一份交叉验证数据,会间接「泄漏」信息。规范做法:**先留出一个完全不碰的测试集**,在剩余数据上做交叉验证调参,最后用测试集做一次最终评估。

**Q:时间序列数据能随机折分吗?**
不能!随机打乱会用「未来」预测「过去」,造成数据泄漏。要用 `TimeSeriesSplit`,保证训练集始终在验证集之前。

**Q:交叉验证为什么比单次划分更可靠?**
它把评估在 K 个不同划分上做平均,抵消了单次划分的随机性,给出更稳定、更接近真实泛化能力的估计,还附带一个波动范围(标准差)。

## 动手作业

1. **手动复现**:不用 `cross_val_score`,自己用 `KFold` 写循环,逐折训练评估并求平均,验证结果一致。
2. **K 的影响**:对同一模型分别用 K=2、5、10、LOO,对比平均分和耗时,体会偏差/方差/速度的权衡。
3. **GridSearchCV**:用 `GridSearchCV` 同时给 KNN 搜索 `n_neighbors` 和 `weights` 两个超参数,打印最佳组合。
4. **分层验证**:构造一个不平衡数据集,对比 `KFold` 和 `StratifiedKFold` 的每折类别分布。
5. **思考题**:为什么「在测试集上反复调参」会导致过于乐观的评估?交叉验证 + 独立测试集如何避免这个陷阱?

## 小结

| 要点 | 说明 |
|---|---|
| 动机 | 单次划分看运气、浪费数据 |
| K 折 | 轮流 1 折验证、K−1 折训练,每样本验证一次 |
| 最终成绩 | K 轮分数的**平均**(± 标准差看稳定性) |
| 常用 K | 5 或 10;数据极少用留一法 |
| 核心用途 | 可靠地**选超参数**、比较模型 |
| 注意 | 不平衡用分层、时间序列用时序切分、保留独立测试集 |

> 🎯 一句话:**交叉验证让模型「多考几次取平均」,把评估从「看运气」变成「看实力」。** 它是超参数调优和模型选型背后那台默默运转的引擎。
