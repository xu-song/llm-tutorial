# 🧪 知识蒸馏

一个几亿参数的大模型准确率很高，但太慢太重，塞不进手机。能不能训练一个**小模型**，让它学会大模型的本事？直接用原始标签训练，小模型效果往往差一截。**知识蒸馏（Knowledge Distillation）** 给出的答案是：**让小模型（学生）去模仿大模型（老师）的输出概率分布**，而不只是模仿硬标签——大模型概率里藏着的「暗知识」，才是它真正值钱的地方。

## 硬标签丢掉了什么：暗知识

假设一张猫的图片，真实标签是 one-hot:`猫=1, 狗=0, 狐狸=0, 汽车=0`。但一个好老师模型的输出可能是：

`猫=81%, 狗=11%, 狐狸=5%, 汽车=2%, 飞机=0.8%`

这里的信息量远超硬标签：老师告诉学生「这张图**像狗、更像狐狸，但绝不像汽车或飞机**」。这种**类别之间的相对相似度**就是**暗知识（dark knowledge）**——硬标签（`猫=1` 其余全 0）把它彻底抹掉了。

## 温度：把暗知识「点亮」

问题是，老师的 softmax 通常很**尖锐**（最高类接近 1，其余趋近 0），暗知识被压得看不见。解决办法是给 softmax 加一个**温度 $T$**：

$$
q_i = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}
$$

- $T=1$：普通 softmax，尖锐。
- $T>1$：分布变**软**，次高类被「点亮」，类间相似结构显现。
- $T\to\infty$：趋近均匀分布。

## 蒸馏损失：学生模仿软标签

学生用**同样的温度 $T$** 产生自己的软标签 $q^{\text{学生}}$，然后最小化它与老师软标签 $p^{\text{老师}}$ 的 **KL 散度**（这正是[前向 KL](/tutorials/forward-reverse-kl)：让学生**覆盖**老师的整个分布）：

$$
\mathcal{L}_\text{soft} = T^2 \cdot D_{KL}\big(p^{\text{老师}}_T \,\parallel\, q^{\text{学生}}_T\big)
$$

那个 $T^2$ 因子是必要的：软化后梯度会缩小约 $1/T^2$，乘回来才能让软损失和硬损失的量级可比。实践中总损失是**两项加权**：

$$
\mathcal{L} = \alpha\,\underbrace{\mathcal{L}_\text{soft}}_{\text{模仿老师软标签}} + (1-\alpha)\,\underbrace{\mathcal{L}_\text{hard}}_{\text{普通交叉熵(真标签)}}
$$

既学老师的暗知识，又不忘真实答案。下面完整跑一遍：

<CodeRunner defaultCode={`
import numpy as np

def softmax_T(z, T=1.0):
    z = np.array(z, float) / T
    z = z - z.max()
    e = np.exp(z); return e / e.sum()

# 老师(大模型)和学生(小模型)对同一张"猫"图的 logits
labels = ["猫", "狗", "狐狸", "汽车", "飞机"]
teacher_logits = [4.0, 2.0, 1.2, 0.3, -0.6]
student_logits = [2.0, 2.1, 0.5, 0.1, 0.0]   # 学生还没学好,把猫和狗搞混了
true_label = 0                                # 真实是猫

T, alpha = 3.0, 0.7

# --- 软损失:学生软标签 vs 老师软标签的 KL(乘 T^2)---
p = softmax_T(teacher_logits, T)   # 老师软标签
q = softmax_T(student_logits, T)   # 学生软标签
kl = np.sum(p * np.log((p + 1e-12) / (q + 1e-12)))
loss_soft = T*T * kl

# --- 硬损失:学生(T=1)对真标签的交叉熵 ---
q_hard = softmax_T(student_logits, 1.0)
loss_hard = -np.log(q_hard[true_label] + 1e-12)

loss = alpha * loss_soft + (1 - alpha) * loss_hard

print("老师软标签 (T=3):", dict(zip(labels, np.round(p, 3))))
print("  -> 暗知识:除了'猫',老师觉得也挺像'狗'和'狐狸'")
print(f"\\n软损失 (KL*T^2) = {loss_soft:.4f}")
print(f"硬损失 (CE)     = {loss_hard:.4f}")
print(f"总损失 = {alpha}*软 + {1-alpha:.1f}*硬 = {loss:.4f}")
`} />

## 为什么有效

- **暗知识是更丰富的监督信号**：一个软标签等于告诉学生「各类之间的相对关系」,信息量远超一个 one-hot,相当于每个样本携带了更多「梯度」.
- **正则化效果**：软标签比硬标签平滑,防止学生对训练集过度自信,泛化更好（和[标签平滑](/tutorials/overfitting-regularization)异曲同工）.
- **小模型也能逼近大模型**：著名的 **DistilBERT** 用蒸馏把 BERT 压缩 40%、提速 60%,却保留了约 97% 的性能.

## 蒸馏什么：三种「知识」

前面蒸馏的是老师**输出层的概率**，但「知识」不止藏在输出里。综述通常按**知识来源**把蒸馏分三类：

| 类型 | 蒸馏什么 | 直觉 |
|---|---|---|
| **响应型（response-based）** | 老师**最后一层的输出**（软标签/logits） | 最简单常用，就是本篇前面讲的 |
| **特征型（feature-based）** | 老师**中间层的特征图** | 让学生的中间表示也向老师看齐，适合又深又瘦的学生 |
| **关系型（relation-based）** | 老师**层之间、样本之间的关系** | 不只学「输出是什么」，还学「样本之间的相对结构」 |

> 💡 响应型只看最终概率，像只对答案；特征型像连解题的中间步骤一起对；关系型则学「这些题目彼此有多像」。三者可组合，但简单叠加常有信息冗余。

## 怎么蒸馏：三种「方案」

再按**训练方式**分，又有三种方案——这条轴是理解[在线蒸馏](/tutorials/on-policy-distillation)的关键：

| 方案 | 老师状态 | 数据来自谁 |
|---|---|---|
| **离线蒸馏（offline）** | **预训练好、固定不动** | 老师（或数据集） |
| **在线蒸馏（online）** | 老师与学生**同时训练** | 可含**学生自己生成**的样本 |
| **自蒸馏（self）** | 老师 = 学生自己（或早期快照） | 自己 |

本篇前面讲的都是**离线**方案：老师是冻结的、数据由老师/数据集提供，学生被动模仿。它简单高效，但有个隐患——**学生只在「老师会遇到的情况」下学，一旦自己跑偏到没见过的地方就抓瞎**.**在线 / on-policy 蒸馏**专门解决这个问题，是大模型时代的新主流，下一篇专门讲：[在线蒸馏(on-policy distillation)](/tutorials/on-policy-distillation)。

## 在哪里用

- **模型压缩**：手机端、边缘设备上的小模型,多数是大模型蒸馏来的.
- **大模型蒸馏成小模型**：GPT-4 级别的模型给数据打标/生成回答,蒸馏出更小更便宜的部署模型（近年开源小模型的常见做法）.
- **自蒸馏 / 集成蒸馏**：把多个模型的集成蒸馏进单个模型,兼得精度与速度.

> 🔗 蒸馏、[RLHF](/tutorials/rlhf)、变分推断都在「让一个分布逼近另一个分布」，区别只在**用哪个方向的 KL**：蒸馏用前向（学生覆盖老师），RLHF 用反向（策略朝偏好收窄）。理解了[前向 vs 反向 KL](/tutorials/forward-reverse-kl)，这些方法就串成了一条线。

### KDLoss：论文配方的忠实直译

torchdistill 的 `KDLoss` 把 Hinton 论文第 2 节的配方**原样**写进一个类里——软损失、硬损失、加权组合一个不缺，是三份实现里最清晰的一版：

```python
# torchdistill/losses/mid_level.py KDLoss.forward（节选，注释为本站所加）
    def forward(self, student_io_dict, teacher_io_dict, targets=None, *args, **kwargs):
        # 用 forward hook 从两个模型的指定模块里抓出 logits
        # （路径由 YAML 配置指定，学生和老师的模块路径可以不同）
        student_logits = student_io_dict[self.student_module_path][self.student_module_io]
        teacher_logits = teacher_io_dict[self.teacher_module_path][self.teacher_module_io]
        # 软损失：两边同除温度 T 后做 KL。
        # 注意参数顺序：F.kldiv 的第一个参数是「输入」（学生的 log 概率），
        # 第二个参数是「目标」（老师的概率）——合起来正是 D_KL(老师 ‖ 学生)
        soft_loss = super().forward(
            torch.log_softmax(student_logits / self.temperature, dim=1),
            torch.softmax(teacher_logits / self.temperature, dim=1)
        )
        # 不传 targets 或 alpha=None 时，退化为纯软损失
        if self.alpha is None or self.alpha == 0 or targets is None:
            return soft_loss

        # 硬损失：学生 logits 不除温度（T=1），对真实标签做普通交叉熵
        hard_loss = self.cross_entropy_loss(student_logits, targets)
        # 总损失：论文第 2 节的加权组合。
        # 软损失乘 T^2：梯度量级随 1/T^2 缩小，乘回来两项才可比
        return self.alpha * hard_loss + self.beta * (self.temperature ** 2) * soft_loss
```

四个细节对着论文看：

- **`student_logits / self.temperature` 与 `teacher_logits / self.temperature`**：两边必须用**同一个温度**——老师先用 $T$ 软化出软标签，学生再用**同一个** $T$ 产生自己的分布去匹配，这正是 Eq(1) 的 softmax 写法。
- **`self.temperature ** 2`**：Hinton 论文说得很直白——「soft targets 产生的梯度量级随 $1/T^2$ 缩放，所以必须乘回 $T^2$」，否则温度一高软损失就被压得没声音，软硬两项的相对权重全乱。教程前面公式里的 $T^2$ 因子，落地就是这五个字符。
- **`alpha` 配 `beta`**：类里 `self.beta = 1 - alpha`（构造函数里这句被省略了），即 $\mathcal{L}=\alpha\,\mathcal{L}_{CE}+(1-\alpha)\,T^2\,\mathcal{L}_{KL}$——和教程前面的 $\alpha\cdot$软 $+(1-\alpha)\cdot$硬 **符号约定相反**但结构相同（alpha 加权的是硬项）。论文原文只说两项加权、没给编号公式，各实现的记号习惯不统一，读代码时先看清 alpha 到底配哪一项。
- **老师侧不反传**：`KDLoss` 本身没有 detach——隔离发生在框架层。`torchdistill` 的 `DistillationBox.forward_process` 里，老师默认整个被 `freeze_module_params` 冻结，前向也包在 `torch.no_grad()` 里跑：

```python
# torchdistill/core/distillation.py get_teacher_output（节选，注释为本站所加）
        if self.teacher_updatable:
            # 在线蒸馏场景：老师也要训练，正常建梯度图
            teacher_outputs = self.teacher_forward_proc(
                self.teacher_model, sample_batch, targets, supp_dict, **kwargs
            )
        else:
            # 离线蒸馏（默认）：老师冻结，前向不建梯度图，
            # 梯度只流向学生——「不反传进老师」在代码里的样子
            with torch.no_grad():
                teacher_outputs = self.teacher_forward_proc(
                    self.teacher_model, sample_batch, targets, supp_dict, **kwargs
                )
```

同一个 `if` 同时服务本篇讲的**离线**蒸馏和下一篇的**在线**蒸馏——区别只是「老师要不要跟着学」，这正是「怎么蒸馏：三种方案」一节那张表在代码里的化身。

### DistilBERT：工业配方的三项组合

DistilBERT 的官方训练代码（`distiller.py`，现居 `huggingface/transformers-research-projects` 仓库）把同一个软损失写进了更大的组合里：

```python
# transformers-research-projects/distillation/distiller.py（节选，注释为本站所加）
            s_logits, s_hidden_states = self.student(
                input_ids=input_ids, attention_mask=attention_mask
            )  # (bs, seq_length, voc_size)
            # 老师前向包在 no_grad 里：不建梯度图，不反传进老师
            with torch.no_grad():
                t_logits, t_hidden_states = self.teacher(
                    input_ids=input_ids, attention_mask=attention_mask
                )  # (bs, seq_length, voc_size)
        ...
        # 软损失：与 KDLoss 完全同构——两边同除 T，KL 后乘 T^2
        loss_ce = (
            self.ce_loss_fct(
                nn.functional.log_softmax(s_logits_slct / self.temperature, dim=-1),
                nn.functional.softmax(t_logits_slct / self.temperature, dim=-1),
            )
            * (self.temperature) ** 2
        )
        loss = self.alpha_ce * loss_ce

        # 硬损失：学生对 MLM 标签的交叉熵（BERT 的原始训练目标）
        if self.alpha_mlm > 0.0:
            loss_mlm = self.lm_loss_fct(s_logits.view(-1, s_logits.size(-1)), lm_labels.view(-1))
            loss += self.alpha_mlm * loss_mlm
        ...
        # 特征型蒸馏：师生最后一层隐藏状态方向的余弦相似度
        if self.alpha_cos > 0.0:
            ...
            target = s_hidden_states_slct.new(s_hidden_states_slct.size(0)).fill_(1)  # (bs * seq_length,)
            loss_cos = self.cosine_loss_fct(s_hidden_states_slct, t_hidden_states_slct, target)
            loss += self.alpha_cos * loss_cos
```

对照教程概念，这正好是「蒸馏什么」一节的**组合示范**：`loss_ce` 是响应型（软标签），`loss_cos` 是特征型（中间层方向对齐），`loss_mlm` 则是硬标签正则。论文的消融显示组合有效——同时去掉 `L_cos` 和 `L_mlm` 只留软损失，GLUE 宏平均掉约 3 分。默认超参（`train.py`）取 $T=2$、`alpha_ce=0.5`，即软硬各半。注意它没有像 `KDLoss` 那样把 $(1-\alpha)$ 挂在软损失上，而是给**每一项独立配一个 alpha**——论文里的两项加权到了工程里长成了多项线性组合，这是配方复杂化后的常见演化。

### TRL DistillationTrainer：新一代的写法

到了大模型时代，HuggingFace TRL 的 `DistillationTrainer` 换了一套骨架：数据由学生 on-policy 生成、损失从 KL 家族换成广义 JSD。但**温度软化**和**老师不反传**这两件最核心的事，代码形态几乎没变：

```python
# trl/trainer/distillation_trainer.py _chunk（节选，注释为本站所加）
        # 老师是固定目标：logits 在 no_grad 下计算，不建 autograd 图、不攒梯度
        # （teacher_logits 从这里开始就是 detached 的，下游全部继承这一点）
        with maybe_gather_lm_head_ctx(w_t, b_t), torch.no_grad():
            teacher_logits = (h_t @ w_t.to(h_t.dtype).t()).float()
            if b_t is not None:
                teacher_logits = teacher_logits + b_t.float()
        ...
        # 蒸馏温度：做散度之前把师生两边的分布都软化
        if temperature != 1.0:
            student_logits = student_logits / temperature
            teacher_logits = teacher_logits / temperature

        student_log_probs = F.log_softmax(student_logits, dim=-1)
        teacher_log_probs = F.log_softmax(teacher_logits, dim=-1)

        # beta: 0=前向 KL，1=反向 KL，其余为广义 JSD。
        # F.kl_div(input, target) 算的是 target * (log target - input)，
        # 所以参数顺序相对论文记号是「交换过」的
        if beta == 0.0:
            jsd = F.kl_div(student_log_probs, teacher_log_probs, reduction="none", log_target=True)
        elif beta == 1.0:
            jsd = F.kl_div(teacher_log_probs, student_log_probs, reduction="none", log_target=True)
```

这里有两点和经典配方的分岔，正好呼应「讨论与展望」一节：其一，默认散度是**反向 KL**（`beta=1.0`）而非 Hinton 的前向——mode-seeking，学生不会摊平到老师学不像的多样性上；其二，代码里**没有 $T^2$ 补偿**——因为 on-policy 蒸馏不再混合硬标签损失，软损失自己定标度，无需和谁对齐量级。经典配方里「为混合而补偿」的零件，在新配方里整个拆掉了。$T^2$ 与否不是对错问题，而是「有没有第二项损失要配平」的问题。

其余实现细节见源码：[transformers-research-projects/distillation](https://github.com/huggingface/transformers-research-projects/tree/main/distillation)、[torchdistill/losses/mid_level.py](https://github.com/yoshitomo-matsubara/torchdistill/blob/main/torchdistill/losses/mid_level.py)、[trl/trainer/distillation_trainer.py](https://github.com/huggingface/trl/blob/main/trl/trainer/distillation_trainer.py)。想自己动手改，从 torchdistill 的 `KDLoss` 起步最省力：去掉 `** 2` 看 alpha 失衡、把 `softmax` 换成 logit 直接回归、再翻一个 `if` 让老师也训练——「动手作业」的四个实验它都装得下。

## ❓ 常见问题 FAQ

**Q：温度 $T$ 怎么选？**
常用 2~10。太小暗知识出不来，太大分布过平、区分度下降。$T$ 是超参数，需按验证集调。注意：**训练时用高温，部署推理时把 $T$ 调回 1**。

**Q：一定要用 KL 吗？能用 MSE 吗？**
主流用 KL（等价于软标签上的交叉熵）。也有直接匹配 logits 的做法（相当于高温极限下的 MSE）。此外还能蒸馏中间层特征（feature distillation），不止蒸馏最后的概率。

**Q：学生一定要比老师小吗？**
通常是，但不绝对。**自蒸馏**里学生和老师结构相同，靠软标签的正则化效果也能涨点；还有「学生反超老师」的现象（born-again networks）。

**Q：蒸馏和迁移学习什么区别？**
迁移学习是**搬参数**（拿预训练权重接着训）；蒸馏是**搬行为**（模仿输出分布，两个模型结构可以完全不同）。

## ✏️ 动手作业

1. **温度扫描**：改代码里的 `T`（1、3、6、10），打印老师软标签，观察暗知识如何随温度显现，以及软损失量级怎么变。
2. **权重 $\alpha$**：把 `alpha` 从 0（只用硬标签）扫到 1（只用软标签），思考纯软标签会丢掉什么。
3. **学生进步**：手动把 `student_logits` 改得更接近老师，看软损失如何下降。
4. **验证 $T^2$**：去掉 `T*T` 因子，对比不同 $T$ 下软/硬损失的量级失衡，理解这个因子为什么必要。

## 🔭 讨论与展望

经典知识蒸馏（Hinton 2015）已经十年了，它仍是工业压缩的主力，但「温度 + 前向 KL + 离线」这套原配方在今天看得到了不少补丁。

### ⚠️ 当前方法的局限

- **离线方案带来暴露偏差**。老师固定、数据预生成，学生只在「老师会遇到的输入」上练过；一旦自己生成时跑偏到没见过的状态，就一步错步步错。这是离线蒸馏最根本的病，长序列/推理任务上尤其明显——也是 [on-policy 蒸馏](/tutorials/on-policy-distillation)要解决的核心问题。
- **前向 KL 逼学生摊平到学不像的多样性上**。前向 $D_{KL}(p_\text{老师}\parallel q_\text{学生})$ 迫使学生**覆盖**老师所有模式，容易摊平到学不像的多样性上、甚至给老师低概率的类放质量。对「要学生抓住老师的具体行为」不如反向 KL（mode-seeking）干脆。
- **温度 $T$ 是个手调旋钮，缺乏原理性选择准则**。$T$ 太低暗知识被压没、太高分布趋近均匀失去信息；实践中要扫，且最优 $T$ 随老师、数据、任务变，缺乏原理性选择准则。
- **暗知识依赖老师质量，也搬运偏见**。学生只能学到老师「会」的；老师分类错的那张图，它的软标签也是错的——蒸馏搬运能力，也搬运偏见。
- **只对齐输出，丢失了中间层结构信息**。经典蒸馏只对齐最终输出分布，不传老师中间层的特征表示；对判别任务够用，对需要老师「思考方式」的任务（推理链、注意力模式）信息利用率低。

### 🚀 前沿进展

1. **on-policy 蒸馏 + GKD**。让学生自采样、老师逐 token 用反向 KL 打分，补暴露偏差；GKD 用「数据源 × 损失方向」两个旋钮把离线/在线/前向/反向统一。详见[下一篇](/tutorials/on-policy-distillation).
2. **特征蒸馏（feature distillation）**。不只对齐输出，还让学生中间层对齐老师中间层（FitNets 及后续）：传「怎么思考」而不只是「答什么」，在视觉任务上常带来明显增益。
3. **数据蒸馏（data distillation）**。反过来——把「老师」蒸馏进数据集：用老师生成/筛选高质量数据，学生用普通 SFT 训练。把蒸馏从「对齐 logits」变成「提纯数据」，工程上更省心。
4. **自蒸馏（self-distillation）**。把一个模型蒸回自己（或同架构新初始化）：去掉噪声、收敛到更稳的解；Thinking Machines 的实验显示自蒸馏能以 7~10× 更少梯度步追平 RL 训练的老师——说明瓶颈常在探索而非容量。
5. **跨模态 / 跨架构蒸馏**。把视觉老师蒸给文本学生、或把大 Transformer 蒸给 RNN/Mamba 等异构学生；难点在中间层对齐变得不可行，只能靠输出分布对齐。

### 🤔 反思

1. **蒸馏是终点，还是中途一站？** 整个生态越来越依赖少数几个大模型当老师：DistilBERT、各路小模型越来越强，但它们的「强」很多是从某个闭源大模型蒸出来的——蒸馏在搬运能力，也在**集中能力**。如果蒸馏是终点，开源小模型的上限就永远被少数老师的上限锁死吗？更可能的情况是蒸馏只是**中途一站**：学生先靠蒸馏拿到「会做题」的基础，再用 RL / 自对弈 / 环境反馈**自己产生新能力**——从「模仿老师」过渡到「站在老师肩膀上探索老师没去过的地方」。

2. **能力能被搬运，那它能被创造吗？** 蒸馏本质是「把老师会的搬给学生」，变不出老师不会的。这意味着只要依赖蒸馏，学生就永远超不过老师——能力的「源头」始终是那个被训练出来的老师（它用了 RL、用了人类反馈、用了海量数据）。一个生态若只蒸馏不训练新老师，是在慢慢耗尽源头活水吗？（注意：「超不过」说的是**能力上限**，不是测试精度——同架构同数据下 student 靠正则化红利超过 teacher 的反例，见[学生超越老师](/tutorials/student-beats-teacher)篇。）

3. **为什么本教程把它放在「前沿与对齐」？** 因为它已经从 2015 的模型压缩技术，长成了今天大模型能力流动的主管道——大模型的能力怎么流向小模型、怎么流向边缘设备、怎么流向下游任务，都靠它。理解蒸馏，就是理解今天 AI 能力的「输血系统」——但输血系统本身，不造血。

> 🎯 **一句话**：经典蒸馏把「能力搬运」做到了便宜、稠密、可缓存；但搬运的天花板是老师本身——所以下一篇要看 on-policy 蒸馏怎么补它的暴露偏差，以及更远的「学生自己长出新本事」。

## 📌 小结

| 概念 | 含义 |
|---|---|
| 暗知识 | 软标签里的类间相似度，硬标签给不了 |
| 温度 $T$ | 软化 softmax，$T>1$ 点亮暗知识 |
| 软损失 | $T^2\cdot D_{KL}(\text{老师}\parallel\text{学生})$，前向 KL |
| 总损失 | $\alpha\cdot$软 $+(1-\alpha)\cdot$硬 |

> 🎯 一句话记住：**知识蒸馏 = 让小学生模仿大老师软化后的概率分布，学的是硬标签给不了的「类间相似度」暗知识。** 这是把大模型能力压进小模型、跑上手机的核心技术。

> 🔄 但上面讲的都是**离线**蒸馏：老师固定、学生被动模仿老师给的数据。学生一旦自己跑到没见过的地方就会「一步错、步步错」。下一篇看新范式——[在线蒸馏(on-policy distillation)](/tutorials/on-policy-distillation)：让学生**自己生成**内容、老师逐 token 打分，大模型蒸馏的当红方案。
