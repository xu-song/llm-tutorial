# MiniMax-M3：块稀疏注意力与原生多模态

2026 年 6 月，MiniMax 发布了技术报告「MiniMax Sparse Attention」：在 GQA 骨干上做**块级稀疏注意力**（MSA），配一套专门协同设计的 GPU 内核，在 1M 上下文下把每 token 注意力计算量降为 1/28.4，prefill 提速 14.2×、decode 提速 7.6×（H800 实测），而 109B 实验模型与全注意力基线在绝大多数基准上打平。<Cite n={1} />生产模型 MiniMax-M3（原生多模态、1M 上下文）已随论文开源。<Cite n={3} />这篇笔记拆三件事：Index Branch 怎么选块、训练侧的 KL 对齐与两条落地路线（从头训 vs 续训）、以及内核协同设计怎么把理论省的 FLOPs 变成真实加速——并与 [DeepSeek-V3.2](/papers/deepseek-v3-2) 的 DSA 对照，看两条稀疏注意力路线的分野。

> 📌 前置：需要熟悉 [Transformer 的缩放点积注意力](/papers/attention-transformer)与 GQA；稀疏注意力的另一条路线见 [DeepSeek-V3.2](/papers/deepseek-v3-2)（DSA：token 级选择、MLA 骨干）。

## 一、动机：1M 上下文下，注意力才是部署瓶颈

Agentic 工作流、仓库级代码理解、持久记忆都要求模型在数十万到百万 token 上联合注意，而 softmax 注意力的 $\mathcal{O}(N^2)$ 成本让这不可行。现有解法各留一个尾巴：线性/递归注意力换掉了精确 softmax；推理时稀疏化（H2O、SnapKV、Quest 等）继承了全注意力的训练成本，且至少有一个推理阶段仍是全注意力速度。

MSA 的立场是**保留精确 softmax、只裁剪感受野，并且让选择器参与预训练**。<Cite n={1} />与最近的同类（DSA、MoBA、NSA）相比，它的两个自我设限恰恰是卖点：① 选择以 **GQA 组**为单位共享——同组 16 个 query 头用同一份块选择，KV 读取保持连续；② 选择是**块级**的($B_k=128$ 个 token 一块)，块粒度让稀疏访存对 GPU 友好。报告的原话：per-GQA-group Top-k 共享 + 块级选择，「multi-group block-granular retrieval while keeping KV reads contiguous」。<Cite n={[1,5]} />

## 二、MSA：一个只管选块的轻量索引器

### 2.1 Index Branch：单 KV 头打分 + 块最大池化 + Top-k

设序列长 $N$，块大小 $B_k$，共 $B=\lceil N/B_k\rceil$ 个块。Index Branch 极其轻量——每层只加**两个投影**:<Cite n={1} />

$$
\mathbf{Q}^{\rm idx}=\mathbf{X}\mathbf{W}_{q}^{\rm idx}\in\mathbb{R}^{N\times H_{kv}\times d_{\rm idx}},\qquad
\mathbf{K}^{\rm idx}=\mathbf{X}\mathbf{W}_{k}^{\rm idx}\in\mathbb{R}^{N\times 1\times d_{\rm idx}}
$$

注意形状：query 侧每个 **GQA 组**一个索引头(共 $H_{kv}$ 个)，key 侧全模型**共享一个头**，$d_{\rm idx}\ll d_h$。每个 GQA 组 $r$ 独立打 token 分，再对块内取最大值汇聚成块分：

$$
\mathbf{S}^{\rm idx,(r)}_{i,j}=\frac{(\mathbf{Q}^{\rm idx})^{(r)}_{i}(\mathbf{K}^{\rm idx})_{j}^{\top}}{\sqrt{d_{\rm idx}}},\qquad
M^{\rm idx,(r)}_{i,b}=\max_{j\in\mathcal{B}_b,\;j\le i}\mathbf{S}^{\rm idx,(r)}_{i,j}
$$

(j>i 的未来块计 $-\infty$，因果性内建。)然后每个组独立 Top-k 选块，局部块（包含 query 自身位置的不完整块）无条件入选：

$$
\mathcal{I}_{i}^{(r)}=\operatorname{TopK}_{b\in\{1,\dots,B\}}\big(M^{\rm idx,(r)}_{i,\cdot},\,k\big)
$$

**Main Branch** 只在被选中的块上做标准精确注意力，组内所有 query 头共享同一份选择：<Cite n={1} />

$$
\mathbf{O}_{i}^{(h)}=\operatorname{softmax}\Big(\frac{\mathbf{Q}_{i}^{(h)}\big(\mathbf{K}^{(r)}[\mathcal{I}_{i}^{(r)}]\big)^{\top}}{\sqrt{d_{h}}}\Big)\mathbf{V}^{(r)}[\mathcal{I}_{i}^{(r)}],\qquad h\in\mathcal{H}_{r}
$$

部署配置 $B_k=128$、$k=16$：每个 query（每个 GQA 组）只看 **$16\times128=2{,}048$ 个 KV token**——1M 上下文下，注意力预算不随序列长度增长。<Cite n={1} />复杂度对比：

$$
F_{\rm GQA}(N)=2H_{q}d_{h}N^{2},\qquad
F_{\rm MSA}(N)=\underbrace{H_{kv}d_{\rm idx}N^{2}}_{\text{Index Branch}}+\underbrace{4H_{q}d_{h}NkB_{k}}_{\text{Main Branch}}
$$

索引器仍是平方，但 $H_{kv}d_{\rm idx}\ll H_{q}d_{h}$(实验模型 4×$d_{\rm idx}$ vs 64×128)，主注意力从 $\mathcal{O}(N^2)$ 降到 $\mathcal{O}(Nk B_k)$。1M 上下文下合计**每 token 注意力 FLOPs 降为 1/28.4**。<Cite n={1} />

### 2.2 训练：KL 对齐 + 梯度截断 + 索引器热身

索引器怎么学？不靠语言建模梯度，靠**蒸馏主分支自己的注意力分布**：把 Main Branch 在选中 token 上的组平均分布当教师，索引分布当学生，<Cite n={1} />

$$
\mathcal{L}_{\rm KL}=\frac{1}{NH_{kv}}\sum_{i=1}^{N}\sum_{r=1}^{H_{kv}}\mathbb{D}_{\mathrm{KL}}\big(\operatorname{stopgrad}(P^{(r)}_{i,\cdot})\,\big\|\,P^{{\rm idx},(r)}_{i,\cdot}\big),\qquad
\mathcal{L}=\mathcal{L}_{\rm LM}+\lambda\sum_{\rm layers}\mathcal{L}_{\rm KL}
$$

两个精心的隔离：教师分布 $\operatorname{stopgrad}$，KL 只更新索引器两个投影、不碰主分支；索引器输入也过 $\operatorname{stopgrad}(\mathbf{X})$，辅助损失不向主干回传梯度。**索引器热身**：最初若干迭代双分支都跑全注意力、只用 KL 训索引投影，之后再切换到稀疏模式——避免随机选择器早期把主干带偏。<Cite n={1} />训练动态很健康：KL 损失与选择召回率(block recall / score recall)在稀疏续训全程保持稳定。

### 2.3 两条落地路线：从头训 vs 续训

- **MSA-PT**（from scratch）：从头稀疏预训练，先 40B token 索引器热身，之后全程稀疏；
- **MSA-CPT**（continued pretrain）：从已训好 2.6T token 的 GQA 全注意力 checkpoint 出发，替换注意力层为 MSA，续训 400B token（同样 40B 热身）。**无需预训练知识迁移，已有稠密 checkpoint 可近无损转换**——这对存量模型是巨大的工程红利。<Cite n={1} />

用 numpy 把 MSA 的「打分 → 块最大池化 → 组内独立 Top-k → 稀疏注意力」走一遍（以最后一个 token 为 query），并对比全注意力的计算量：

rng = np.random.default_rng(7)

G = Hq // Hkv                      # 每组的 query 头数 = 16

## 三、内核协同设计：把 FLOPs 省的变成时间省的

稀疏注意力的经典陷阱：理论省了计算，GPU 上却不快。<Cite n={[1,4]} />MSA 的三个内核决策值得逐条读：

1. **免 exp 的 Top-k**：softmax 保序($s_i\le s_j \iff \mathrm{softmax}(s)_i\le\mathrm{softmax}(s)_j$)，所以选择直接用原始分，跳过 max/exp/sum。<Cite n={1} />Top-k 本身用每线程寄存器流式维护 k 元素最小堆(32 lane 各扫 1/32 行、共享内存堆、k 轮 shuffle 合并)，部署设置($B=8192$ 块选 16)下比 `torch.topk` 快 5.1×、比 TileLang radix-select 快 3.7×；
2. **KV-outer 迭代 + query 收集**：稀疏 prefill 里每个 query 选的块不同，Q-outer（按 query 外层迭代）无法把 query 拼进大矩阵；KV-outer 反过来按 KV 块外层迭代、收集选中该块的所有 query——同一 tile 的所有 gathered query 共享 KV 操作数，$\lceil 128/G\rceil$ 个 query 位置与它们 G 个头拼成 128×128 的 MMA。算术强度 $\tfrac{2}{3}B_k\approx 85$ 远高于 Q-outer 的 $G=16$;
3. **热点块预调度**：被几乎所有 query 选中的块（如 sink 块）会让 one-CTA-per-tile 映射失衡；调度内核把热点 KV tile 沿 query 维切成 ~$2kB_k$ 的块分摊到多个 CTA，配 split-K LSE 两阶段合并。

## 五、消融：sink 与局部窗口不需要硬编码

附录的消融回答了两个「想当然」的问题：<Cite n={1} />

- **learnable sink 要不要加？** 测试了 GPT-OSS 式可学习 sink logit：它在部分头吸走大量注意力，但**并没有消除首 token 的隐式 sink**——学到少注意力的头里，首 token 仍是主导 sink；下游 PPL 也无一致改善。最终方案不加，首 token 自然承担 sink 角色；
- **首块与局部窗口要不要强制选？** 早期实验强制选首块（sink）+ 固定局部窗口作稳定机制；去掉之后，训练出的模型**自己学出了这两种结构**（需要时注意力集中在前缀、近邻 token 高频入选），标准质量与长上下文检索几乎不变。最终配方只强制包含 query 自身所在的不完整块。

学到的注意力模式还很有结构：所有头都在局部对角线与 sink 列上放高概率，剩余预算留给少数长程位置——而**非局部选择在各 GQA 组之间明显不同**（层 18 上四个组各自选中不同的长程条纹），这正是组独立选择的意义。块大小 32/64/128 对结果影响很小；动态选择优于 FLOP 匹配的滑动窗口基线。

## 六、与 DSA 的对照：两条稀疏注意力路线

把 MSA 与 [DeepSeek-V3.2](/papers/deepseek-v3-2) 的 DSA 并排放，2026 年稀疏注意力的设计空间一目了然：<Cite n={[1,2]} />

| 维度 | MSA（MiniMax） | DSA(DeepSeek) |
|---|---|---|
| 骨干注意力 | GQA | MLA（MQA 模式实例化） |
| 选择粒度 | 块级($B_k=128$) | token 级（每 query 选 2,048 个） |
| 选择共享 | 每 GQA 组独立（16 头共享） | 所有 query 头共享单一 Top-k |
| 索引器 | 2 个投影，组 query 头 + 共享 key 头 | 多头 ReLU lightning indexer |
| 索引器训练 | KL 对齐主分支分布，梯度截断 | 先 KL 对齐热身，后与主干联合 |
| 落地方式 | 从头训 / checkpoint 续训 400B | 从 V3.1-Terminus 续训（2.1B 热身 + 943.7B） |
| 主注意力 | 精确 softmax，仅限选中块 | 精确注意力，仅限选中 MLA 潜向量 |

共同点是「精确 softmax + 学习的选择器 + 续训可行」；分歧在粒度与共享策略——MSA 押注块粒度换访存连续与内核效率（GQA 骨干普及度也高），DSA 押注 token 粒度换选择精度。两者都报告了「性能持平 + 长上下文成本大降」，说明**瓶颈已经从『稀疏会不会掉点』转移到『内核能不能兑现』**——这也是两篇报告都用大篇幅写内核的原因。

## 七、局限与批判

1. **长程精确检索的残余差距**：HELMET 的 Rerank/RAG 子任务 −2.10 是最明显的掉分点；报告的展望也承认，更长稀疏训练、更大推理预算或更强索引打分函数都是待选项。每 query 2,048 token 的硬预算，终究会碰到需要「海里捞针」的任务；
2. **实验规模与生产规模脱节**：论文实验是 109B/6B 模型 + 3T token；生产模型 MiniMax-M3（原生多模态、1M 上下文）只给了 HF 发布链接，未随论文给出同等深度的对照实验——「MSA 在生产规模同样成立」目前是承诺而非证据；
3. **索引器的上限**：单共享 key 头 + 组 query 头的设计极简，但表达力也随之受限；块内 max 池化意味着块选择由单个最强 token 决定，块内噪声 token 可能劫持选择；
4. **组内共享的代价**：同组 16 个 query 头被迫共用一份选择——论文的注意力模式图显示组间确实分化，但组内不同头若需要不同感受野，只能靠 $H_{kv}$ 个组的数量兜底，头级个性被抹平。

## 小结

- **MSA = GQA 上的块稀疏注意力**：Index Branch（每 GQA 组一个索引头 + 全局共享 key 头）给 KV 块打分，组内独立 Top-k 选 $k=16$ 块($B_k=128$),Main Branch 只在选中块上做精确 softmax——每 query 固定 2,048 token 预算，1M 上下文下注意力 FLOPs 降为 1/28.4;
- **训练**：KL 对齐主分支组平均分布（双向 stopgrad 隔离）+ 索引器热身；从头训(MSA-PT，数学/多模态/检索更强)与 checkpoint 续训（MSA-CPT，贴住基线）双路线；
- **内核**：免 exp Top-k（寄存器最小堆，5.1× 于 torch.topk）、KV-outer 迭代 + query 收集(算术强度 $\tfrac{2}{3}B_k$ vs $G$)、热点块预调度——H800 实测 prefill 14.2×、decode 7.6×;
- **消融哲学**：learnable sink 与强制局部窗口都不需要——模型自己学得会；最终配方只强制自身所在块。

MSA 的信息量在于克制：不加值头、不强制 sink、不动主分支结构，把全部设计预算押在「选择粒度 + 共享策略 + 内核」三件事上。它与 DSA、MoBA、NSA 一起，把稀疏注意力从推理期技巧变成了**预训练期的一等公民**——当每 token 只看 2,048 个 KV 成为可训练的默认，1M 上下文的部署经济学就被改写了。
