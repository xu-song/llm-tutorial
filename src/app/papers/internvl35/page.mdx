# InternVL3.5：级联 RL 与按需分配的视觉预算

2025 年 8 月，上海 AI Lab 发布了 [InternVL3.5](https://arxiv.org/abs/2508.18265)：从 1B Dense 到 241B-A28B MoE（代号 Flash）共十档的视觉语言模型家族，用「原生多模态预训练 → 监督微调 → **级联强化学习**」三阶段训练。<Cite n={1} />论文的三个贡献恰好对应三个工程痛点：**Cascade RL** 回答「RL 后期怎么继续涨」、**Visual Resolution Router** 回答「不同任务到底需要多少视觉 token」、**DvD（视觉语言解耦部署）** 回答「VLM 推理为什么必须背着视觉塔」。<Cite n={1} />旗舰 241B-A28B 在 OpenCompass 等综合榜上超越 Qwen3-235B、GPT-5、Gemini 2.5 Pro，多模态推理较 InternVL3 提升 16%。<Cite n={1} />这篇笔记拆解这三件事。

> 📌 前置：RL 部分与 [GRPO](/papers/grpo-deepseek-r1) 的组内基线一脉相承；架构是经典的 ViT–MLP–LLM，与 [Transformer](/papers/attention-transformer) 对照读即可；RL 基础可参考 [策略梯度](/tutorials/policy-gradient) 与 [GRPO/RLVR](/tutorials/grpo-rlvr)。

## 一、动机：多模态 RL 的三道坎

InternVL3 到 3.5 的迭代，针对的是多模态 RL 的三个普遍问题：

1. **难度失配**：RL 训练推进后，初期「中等难度」的任务被模型陆续攻克，奖励信号逐渐稀疏；直接换更难的任务，早期梯度又不稳。
2. **视觉预算一刀切**：OCR 类任务需要高分辨率、海量视觉 token；常识问答只需要低分辨率。统一分辨率意味着「简单任务浪费、难任务不够」。
3. **部署耦合**：视觉塔与 LLM 捆绑部署，视觉编码的算力无法独立伸缩。

模型家族(1B/2B/4B/8B/14B/38B Dense + 9B/12B/30B-A3B/78B-A7B/241B-A28B MoE)全部**参数随机初始化**——不是从 InternVL3 继承权重，而是从头走完「原生多模态预训练 → SFT → Cascade RL」三阶段。<Cite n={1} />这一点值得注意：它是「多模态从预训练第一天就在场」路线的又一次验证，与 Qwen3-VL 的协同训练选择一致。

## 二、架构：ViT–MLP–LLM，不变的是骨架

架构没有大改：ViT 视觉塔 + 两层 MLP 投影 + LLM(语言侧为 Qwen3 系列或 InternLM 系的 MoE/Dense)。<Cite n={[1,2,5]} />重点反而在于「不变」：三个创新全部落在**训练方法与推理策略**上，而非网络结构。这对读者是个有用的信号——2025 年多模态的边际收益已经从架构创新转移到数据课程与 RL 配方，与纯 LLM 的演进节奏同步。

## 三、Cascade RL：离线重放 + 在线优化

级联 RL 分两阶段，共同解决「难度失配」:<Cite n={1} />

**阶段一（离线，难度驱动重放）**：以 SFT 模型为起点，对任务池按难度做**难度驱动的重放采样**（difficulty-driven replay）——每个任务用当前模型的 pass@k 估计通过率，按「学得动」的难度带重新加权采样，做离线策略优化。<Cite n={1} />直觉：一个任务如果 pass@1 已接近 1，梯度趋零；如果 pass@k 全为 0，也几乎学不到（探索打不穿）；**最优教学区间在两者之间**。

**阶段二（在线，off-policy 修正）**：切到在线 RL，策略在训练中持续更新，旧样本通过 off-policy 重要性修正复用，新样本按当前策略的难度分布滚动生成——课程随能力自动爬坡。<Cite n={1} />

用 numpy 把「难度驱动重放」的采样权重实现一遍，感受 pass@k 与采样概率的关系：

<CodeRunner defaultCode={String.raw`import numpy as np

rng = np.random.default_rng(42)
n_tasks = 200

# 模拟任务池:每题一个真实难度(通过概率),难度分布偏两极
p_true = np.clip(rng.beta(0.6, 0.9, size=n_tasks), 0, 1)

# —— 用当前模型的 pass@8 估计每题难度(k=8 次采样) ——
k = 8
passes = rng.binomial(1, p_true[:, None], size=(n_tasks, k)).sum(axis=1)  # 每题 8 次通过几次
pass_at_k = passes / k

# —— 难度驱动重放:采样权重瞄准「学得动」的中间难度带 ——
# 完全掌握(pass@k≈1)与完全打不通(pass@k≈0)的题都降权,
# 中等难度(通过率在 0.2~0.8)的题获得最高采样概率
target = 0.5
w_difficulty = np.exp(-((pass_at_k - target) ** 2) / (2 * 0.25 ** 2))   # 高斯难度核
w_difficulty /= w_difficulty.sum()

# 对照:均匀采样
w_uniform = np.ones(n_tasks) / n_tasks

def describe(w, name):
    band = (pass_at_k > 0.2) & (pass_at_k < 0.8)
    print("%s 采样:落在中等难度带(0.2<pass@8<0.8)的采样预算占比 %.1f%%"
          % (name, 100 * w[band].sum()))

print("任务池难度分布: pass@8=0 的题占 %.0f%%, pass@8=1 的题占 %.0f%%"
      % (100 * (pass_at_k == 0).mean(), 100 * (pass_at_k == 1).mean()))
describe(w_uniform, "均匀  ")
describe(w_difficulty, "重放  ")

# —— 抽一批训练任务,看难度构成 ——
sampled = rng.choice(n_tasks, size=64, p=w_difficulty)
ps = pass_at_k[sampled]
print("\n重放采样 64 题的 pass@8 分布: min=%.2f 中位=%.2f max=%.2f"
      % (ps.min(), np.median(ps), ps.max()))
print("(中位数落在中间难度带 —— 这就是「难度驱动」的含义)")
print("\n阶段二切到在线 RL 后,pass@k 用当前策略滚动估计,")
print("课程随能力自动爬坡;旧样本靠 off-policy 重要性修正继续复用。")`} />

## 四、Visual Resolution Router：按任务分配视觉预算

第二个创新解决「视觉预算一刀切」。同一个模型服务的任务谱系很宽：OCR/文档解析需要高分辨率，而「这张图里有猫吗」只需要低分辨率。固定分辨率意味着简单任务浪费视觉 token、复杂任务分辨率不够。

**Visual Resolution Router** 的思路：训练一个轻量路由器，按输入（任务与图像）动态决定喂给 LLM 的**视觉 token 预算**——难任务多给 token（高分辨率、细粒度 patch），简单任务少给。<Cite n={1} />设可选预算档位为 $\{B_1 < B_2 < \dots < B_m\}$，路由器 $g_\phi$ 输出每档的偏好，推理时按预算裁剪视觉序列：

$$
B^{*} = g_\phi(\text{image},\,\text{task}),\qquad
\mathbf{V}_{\text{in}} = \mathrm{Crop}\big(\mathbf{V},\, B^{*}\big)
$$

效果是「同一模型在不同任务上花不同的视觉算力」——综合精度几乎不掉，平均视觉 token 数大幅下降，推理成本随任务难度弹性伸缩。<Cite n={1} />

用 numpy 模拟一个按任务难度分配 token 预算的路由器：

<CodeRunner defaultCode={String.raw`import numpy as np

rng = np.random.default_rng(7)

# 任务特征:假设 router 从图文联合特征里读出「任务难度」
# (OCR/图表/细粒度识别 -> 难;是/否问答、场景描述 -> 易)
tasks = [
    ("文档 OCR(密集中文表格)", 0.95),
    ("图表数值读取",           0.85),
    ("局部物体计数",           0.55),
    ("场景是室内还是室外",     0.15),
    ("图里有没有猫",           0.05),
]

# 可选视觉 token 预算档位(高分辨率 -> 多 token)
budgets = np.array([256, 512, 1024, 2048, 4096])

# router:难度分 -> softmax over 档位(难度越高,偏好越大预算)
def route(difficulty, temp=0.3):
    logits = np.log(budgets / budgets.min()) * difficulty / temp   # 难度缩放对数预算
    w = np.exp(logits - logits.max()); w /= w.sum()
    return budgets[rng.choice(len(budgets), p=w)], w

print("%-22s %8s %10s" % ("任务", "难度分", "分配预算"))
total_uniform = 0; total_router = 0
for name, d in tasks:
    b, w = route(d)
    total_router += b
    total_uniform += budgets.max()          # 一刀切 = 全部给最大预算
    print("%-22s %8.2f %8d tok  (top-2 档概率 %.2f/%.2f)"
          % (name, d, b, w.max(), np.sort(w)[-2]))

print("\n一刀切(全 4096): %6d tok" % total_uniform)
print("router 分配:      %6d tok  (节省 %.0f%%,难任务仍拿到高预算)"
      % (total_router, 100 * (1 - total_router / total_uniform)))`} />

## 五、DvD：视觉语言解耦部署

第三个创新面向部署。常规 VLM 推理时，视觉塔与 LLM 在同一进程/服务里紧耦合——视觉编码的算力无法独立伸缩，升级 LLM 要连视觉塔一起重部署。

**DvD（Decoupled Vision-language Deployment）** 把两者拆开：视觉编码与语言解码作为独立服务，中间以**视觉 token 表示**（而非原始图像）传递。<Cite n={1} />收益是三重的：视觉塔可以单独扩缩容（OCR 流量高峰只扩视觉服务）；语言侧可以独立换模型/量化；缓存友好——同一张图的视觉 token 编码一次、多处复用。论文报告 **4.05× 部署加速**。<Cite n={1} />

这本质上是把「特征即接口」的微服务思想搬进 VLM：视觉塔输出的 token 序列成为一种稳定的中间协议，上游升级不破坏下游。代价是中间表示体积大于原图（JPEG 压缩率高），网络带宽换算力弹性——在数据中心内部通常划算。

## 六、关键数字与定位

| 维度 | 结果 | 说明 |
|---|---|---|
| 多模态推理 | 较 InternVL3 **+16%** | Cascade RL 两阶段的综合增益 |
| 综合榜（OpenCompass 等） | 241B-A28B 超越 Qwen3-235B、GPT-5、Gemini 2.5 Pro | 旗舰 Flash 档 |
| 部署效率 | **4.05×** 加速 | DvD 解耦部署 |
| 家族宽度 | 10 档（6 Dense + 4 MoE） | 1B 到 241B-A28B 全覆盖 |
| 初始化 | 参数随机初始化 | 非从 InternVL3 继承，原生多模态三阶段 |

定位一句话：**InternVL3.5 把多模态的边际创新从架构挪到了训练课程与推理策略**——Cascade RL 管「RL 的可持续性」、Router 管「视觉算力的按需分配」、DvD 管「部署的解耦」。与前代相比，它不再堆视觉塔的结构改动，而是让同一副骨架在不同难度、不同任务、不同部署形态下都跑到最优工作点。<Cite n={1} />

## 七、局限与批判

- **+16% 的口径**：「多模态推理提升 16%」是相对 InternVL3 的聚合数字，具体基准构成与权重论文有列，但跨版本对比的公平性（数据量、算力是否对齐）需要读者自行核账。
- **Router 的训练信号**:Visual Resolution Router 的难度判别依赖什么监督（任务标签、模型反馈还是启发式）在论文里着墨不多；分布外任务上的路由质量是实际部署的隐患。
- **DvD 的带宽代价**：中间视觉 token 表示远大于压缩图像，跨机房/边缘场景不一定划算；4.05× 是特定部署配置下的数字。
- **继承性为零的成本**：参数随机初始化意味着每个新版本都要付全量预训练算力——与「从上一代继续训」路线相比，迭代成本更高，论文未披露总算力。
- **MoE 小档的意义**：9B/12B Dense 与 30B-A3B MoE 的档位重叠，实用差异需要用户自行基准测试。

## 小结

- **Cascade RL**：两阶段级联——离线「难度驱动重放」（pass@k 估计难度、瞄准学得动的中间带采样）+ 在线 off-policy 优化（课程随能力爬坡）——是多模态推理 +16% 的主要来源。
- **Visual Resolution Router**：轻量路由器按任务动态分配视觉 token 预算，简单任务省 token、难任务保分辨率，精度几乎不掉。
- **DvD**：视觉编码与语言解码拆成独立服务，视觉 token 作为中间协议可缓存、可独立扩缩容，部署加速 4.05×。
- **结果**：241B-A28B 在 OpenCompass 等综合榜超越 Qwen3-235B、GPT-5、Gemini 2.5 Pro；十档家族覆盖 1B 到 241B，全部随机初始化走完三阶段训练。

InternVL3.5 的信号值得记下：**当架构趋同，RL 课程与推理时资源分配成为新的竞争面**。Cascade RL 的「难度重放」思想与 [GLM-4.5](/papers/glm-45) 的两阶段难度课程、[GRPO](/papers/grpo-deepseek-r1) 的可验证奖励是同一方向上的三种工程化；而 Router 与 DvD 提醒我们：多模态的成本大头从来不在训练，在每一次推理。
