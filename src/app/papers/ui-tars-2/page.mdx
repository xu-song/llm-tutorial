# 🖥️ UI-TARS-2:GUI Agent 的多轮强化学习

2025 年 9 月,字节跳动 Seed 团队发布 UI-TARS-2:一个以截图为输入、以界面动作为输出的原生 GUI Agent(不依赖 DOM 等底层信息),底座是 Seed1.6(532M 视觉编码器 + 230B 总参/23B 激活的 MoE)。它的技术报告回答的问题是:**多步、长程、视觉密集的 GUI 操作能力,能不能靠 RL 系统性地训出来?** 核心答案是「多轮 RL」——把「观察-思考-行动」的完整任务轨迹作为训练单元,而非单步动作。OSWorld 47.5、AndroidWorld 73.3、Online-Mind2Web 88.2,均为当时开源 SOTA。这篇笔记拆解四件事:native agent 形式化、数据飞轮与交互式标注、多轮 RL 基础设施与算法、推理时扩展。

> 📌 前置:RL 算法部分对照 [PPO](/papers/ppo-schulman) 与 [GRPO/R1](/papers/grpo-deepseek-r1) 阅读收获最大;agentic 数据合成的另一条路线见 [Kimi K2](/papers/kimi-k2)。

## 一、形式化:Agent 就是一条轨迹上的策略

UI-TARS-2 采用 **native agent** 视角:Agent 是一个参数化策略,把历史上下文、记忆状态与当前环境映射为行为输出。遵循 ReAct 范式,一个 step 是一轮完整的「思考-行动-观察」循环,任务轨迹为

$$
\tau=\{(t_0,a_0,o_0),\;(t_1,a_1,o_1),\;\dots,\;(t_T,a_T,o_T)\}
$$

策略在每一步预测下一对思考与动作:

$$
P(t_n, a_n \mid \text{instruction},\; W_n,\; o_n,\; E_n)
$$

其中 $W_n$ 是**工作记忆**(最近若干步的高保真内容,上下文截断到最近 N 步), $E_n$ 是**情景记忆**(过往 episode 的语义压缩摘要,保留关键意图与结果)。动作空间有两类:GUI 动作(click/type/scroll,游戏操作复用同一套)与 SDK 函数(终端命令、MCP 工具调用)——后者让同一个 Agent 能在纯 GUI 与代码两条通道间切换(BrowseComp 上 GUI-only 7.0 vs 带 SDK 29.6,差距全部来自通道选择)。

## 二、数据飞轮:让数据与模型互相加速

训练数据走 CT(持续预训练)→ SFT → RL 的飞轮循环,论文 Figure 3。冷启动:CT 用 UI-TARS 与 UI-TARS-1.5 的全部数据(网页教程、开源轨迹、内部标注);SFT 用合成生成 + 人工标注构造初始集。之后每轮 RL 的输出经验证函数 $V(s)\to\{0,1\}$ 筛选:

$$
D_{\mathrm{SFT}}^{(t+1)}=D_{\mathrm{SFT}}^{(t)}\cup D_{\mathrm{RFT,high}}^{(t)},\qquad
D_{\mathrm{CT}}^{(t+1)}=D_{\mathrm{CT}}^{(t)}\cup D_{\mathrm{RFT,low}}^{(t)}
$$

高质量样本升入 SFT、低质量回收进 CT;SFT 与 RL 的迭代频率高于 CT,agent 数据在 SFT 中占比远大于 CT。数据侧两个有意思的设计:

- **CT 的 think-aloud 标注**:标注员在自己的真实电脑上边操作边把思考过程说出来,语音经 ASR 转写、LLM 润色、与动作时间对齐——得到「带思维链的真实操作轨迹」;专家与新手双轨并行。
- **SFT 的 on-policy 标注**:交互式标注平台(四层架构:交互层 UI、服务层编排模型命令与人工干预、平台层承载 Computer Use/Phone Use/Tool Use 场景、存储层记录轨迹)里,标注员对模型实时提议的动作「接受或改写」——改写即产生一次高价值的纠错样本,还带命令自动补全、VM 视频流、坐标可视化。

## 三、多轮 RL:把整个轨迹当训练单元

与「单步动作 + 即时奖励」的 RL 不同,多轮 RL 以完整任务轨迹为单元,奖励主要由最终结果决定(游戏用 JS 校验脚本读运行时变量——分数/关卡/生命——给出确定性二元信号;GUI-Browsing 用 LLM-as-Judge 比对目标答案;不可验证的 GUI-General 任务让 UI-TARS-2 自己当生成式 ORM,基于全部文本历史 + 最近 5 张截图打分,在 300 条人工标注轨迹上 F1 = 83.8),再叠加格式奖励与长度惩罚(防提前终止与无限拖延)。

任务面三族:**GUI-Browsing**(维基百科多条件混淆 + 多跳链式条件)、**GUI-General**(690 个网站的离线合成)、**Gameplay**(HTML5/WebGL 小游戏 + LLM 合成游戏,全部跑在浏览器沙箱里)。

算法选 **PPO 而非 GRPO**——论文明确说「PPO 始终以明显优势胜出」,训练曲线奖励更高、波动更低。这对 [GRPO 在推理域的统治地位](/papers/grpo-deepseek-r1) 是个值得注意的反例:多轮交互任务有天然的价值结构(中间状态可复用、critic 能跨步泛化),砍掉 critic 的组内基线反而吃亏。三个针对性改造:

1. **Length-Adaptive GAE**:长序列的优势估计偏方差、短序列偏低偏差,按序列长度 $l$ 调 $\lambda_{\mathrm{policy}}=1-\frac{1}{\alpha l}$($\alpha=0.05$);critic 侧 $\lambda$ 与策略侧解耦;
2. **Value Pretraining**:先冻结策略离线把价值模型训到收敛(GAE $\lambda=1.0$,等价蒙特卡洛回报),再进 RL——价值初始化偏差是多轮长轨迹的顽疾;
3. **Clip Higher**:按 DAPO 把裁剪上下界解耦($\epsilon_{\mathrm{high}}$ 放宽,给低概率动作留上升空间;$\epsilon_{\mathrm{low}}$ 收紧防过早淘汰)。

基础设施是这套方法的真正门槛,论文 Figure 6。核心三件:**异步服务化 rollout**(agent 框架与策略推理解耦)、**流式训练**(动态 rollout 池,完整轨迹凑够最小批量即开训,不完整轨迹保留到后续迭代——类似 Kimi-Researcher 的做法;GUI 轨迹动辄数分钟,等全员到齐会把 GPU 闲置)、**有状态环境**(跨工具调用保留执行状态)。支撑层:数千实例规模的 VM 平台(数千 QPS、VNC/RTC 监控、租约式生命周期),浏览器沙箱每容器多实例 + 弹性调度 + 崩溃自动恢复 + 检查点,兼容 CDP/Playwright,GPU 加速截图;游戏环境重写了 Window timing API,支持时间加速与启动暂停——不改变游戏逻辑的前提下提高采样效率与可复现性。

训练动力学有一个反直觉发现:**熵在训练中上升**。推理域 RL 通常熵单调下降(策略确定性收敛),而 GUI 与游戏实验中熵持续走高——视觉密集、高度交互的环境需要持续探索,模型没有过早塌缩到窄的利用模式;GUI 任务的思考长度与交互步数反而在下降(学会更少的步骤完成任务)。

## 四、垂直 Agent 与合并

RL 阶段按域分别训练四个垂直 Agent(GUI-Browsing / GUI-General / Game / GUI-SDK),再用**参数插值**合并:

$$
\theta^{\mathrm{merge}}=\sum_{k}\alpha_k\,\theta^{(k)},\qquad \sum_k \alpha_k=1,\;\;\alpha_k\ge 0
$$

依据是同一预训练 checkpoint 出发的微调模型在参数空间近似线性模式连接——插值合并保住各垂直域性能的同时给出跨域泛化。论文还试了混合 RL(共享接口训练):混合模型即使每个接口的数据减半仍超过纯 GUI 基线,共享价值模型还提升了方差解释率。

用 numpy 模拟「轨迹级 vs 步级信用分配」与多轮 GAE 的区别:

import numpy as np

rng = np.random.default_rng(3)

# —— 一条轨迹:每步即时奖励,末端才有结果奖励 ——
# 场景:10 步 GUI 操作,只有最后一步决定任务成败(多轮 RL 的典型结构)
T, gamma = 10, 0.99
step_r = rng.uniform(-0.02, 0.02, T)      # 过程奖励(长度惩罚等,几乎为零)
success = rng.random() < 0.5              # 终局:任务是否成功
step_r[-1] += 1.0 if success else 0.0     # 结果奖励集中在最后一步

# —— 信用分配方式 1:轨迹级(整条轨迹同一个优势) ——
traj_return = sum(gamma**k * step_r[k] for k in range(T))
adv_traj = np.full(T, traj_return)        # 每一步拿到同样的信号

# —— 信用分配 2:步级 GAE(λ 平衡偏差-方差) ——
def gae(rewards, lam, values=None):
    T = len(rewards)
    if values is None:
        values = np.zeros(T + 1)          # 无 critic 时退化为折扣回报
    adv = np.zeros(T)
    gae_ = 0.0
    for t in reversed(range(T)):
        delta = rewards[t] + gamma * values[t + 1] - values[t]
        gae_ = delta + gamma * lam * gae_
        adv[t] = gae_
    return adv

values = np.zeros(T + 1)                  # 假设价值模型尚未学到东西
adv_mc   = gae(step_r, lam=1.0, values=values)   # λ=1: 蒙特卡洛(高方差)
adv_td    = gae(step_r, lam=0.0, values=values)   # λ=0: 一步 TD(高偏差)

print("任务结果: %s   轨迹折扣回报 = %.3f" % ("成功" if success else "失败", traj_return))
print("\n各步优势估计(前 5 步 + 末步):")
print("  轨迹级(同信号): ", adv_traj[[0,1,2,3,4,-1]].round(3))
print("  GAE λ=1 (MC):    ", adv_mc[[0,1,2,3,4,-1]].round(3))
print("  GAE λ=0 (TD):    ", adv_td[[0,1,2,3,4,-1]].round(3))
print("\n观察:多轮任务的结果奖励集中在末端,轨迹级把信号均摊给每一步;")
print("     GAE 沿时间反向传播折扣,越早的步分到的信用越少 —— 这就是")
print("     UI-TARS-2 需要 Length-Adaptive GAE 与 Value Pretraining 的原因。")

# —— Length-Adaptive GAE:λ 随序列长度自适应 ——
print("\nLength-Adaptive GAE 的 λ_policy = 1 - 1/(α·l), α=0.05:")
for l in [32, 64, 128, 512]:
    lam = 1 - 1 / (0.05 * l)
    print("  轨迹长度 %4d 步 -> λ = %.3f  (短轨迹偏 TD/低偏差, 长轨迹偏 MC/低方差)" % (l, lam))

## 五、推理时扩展:步数预算换性能

推理时扩展的形态出乎意料地朴素:**放大允许的交互步数**。游戏基准上,性能曲线随步数预算「以近乎单调的阶梯状」持续上升,在超出原始预算数量级的步数上仍在涨分;基线模型曲线很快走平,说明它们无法把额外的交互预算转化为收益。OSWorld 上同样成立——值得注意的是,RL 训练明明在激励模型用更少的步骤完成任务,模型却仍能把更大的步数预算转化为更高的分数,而不是过拟合到「最短路径」策略。论文的解释:策略在跨过任务特定的阈值后继续解锁新的子目标,而不是原地打转。

## 局限与批判

- **长程规划仍是软肋**:Tetris(16.0)与 Sokoban(0.3)在 LMGame-Bench 上近乎失败,论文自己归因于超长视野规划;Gem-11/Hex-frvr 的平台期提示瓶颈来自基座推理能力而非优化步数。
- **ORM 的假阳性**:自举 ORM 的 F1 只有 83.8,假阳性被刻意容忍(正确的中间步骤仍有奖励),但这意味着不可验证任务上的奖励信号天然带噪。
- **PPO 的代价**:与 GRPO 路线相比,多轮 PPO 需要维护跨步复用的价值模型,加上数千实例的环境集群——这套基础设施的复现门槛远高于算法本身。
- **数据域偏斜**:公开 GUI 数据稀缺且已用尽;中文 App 覆盖有限;回顾式思维链标注被验证无效(思维必须在操作时同步产生)。
- **推理时扩展未与尝试选择结合**:论文只放大步数预算;多次采样 + 判别选择(如 self-critic 投票)是社区常见做法,论文未探索,留给后续。

## 小结

- **形式化**:native agent = 轨迹上的参数化策略 $P(t_n,a_n\mid\text{instruction},W_n,o_n,E_n)$;工作记忆(最近 N 步)+ 情景记忆(压缩摘要)的双层记忆让长程任务在截断上下文下可行。
- **数据**:飞轮循环(CT → SFT → RL,验证函数分流高低质量样本)+ think-aloud CT 标注 + on-policy 交互式标注平台(四层架构)。
- **多轮 RL**:PPO(明确胜过 GRPO)+ Length-Adaptive GAE + Value Pretraining + Clip Higher;异步服务化 rollout、流式训练、有状态环境、数千实例 VM/浏览器沙箱;训练中熵上升是持续探索的证据。
- **结果**:OSWorld 47.5、AndroidWorld 73.3、游戏均值超 CUA 2.4 倍;推理时按步数预算扩展,单调涨分;四个垂直 Agent 参数插值合并。

UI-TARS-2 最大的信息量是把「GUI Agent 能不能训」变成了一个工程问题,并且给出了完整答案清单:任务怎么造(混淆/多跳/游戏)、奖励怎么定(结果主导 + 校验脚本)、基础设施怎么搭(异步流式 + 沙箱)、算法怎么调(PPO 三件套)。其中「PPO 在多轮交互域胜过 GRPO」这一条,对 2025 年一边倒的 GRPO 共识是必要的一针清醒剂——**砍 critic 省下的算力,在状态可复用的环境里是要还的**。
